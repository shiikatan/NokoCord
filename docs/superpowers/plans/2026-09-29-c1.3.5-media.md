# C1.3.5 Calls and Apple Music Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use red-green-refactor; live Discord and Automation behavior must remain explicitly manual gates.

**Goal:** Make call and Apple Music state truthful, lifecycle-safe, diagnosable, and testable without adding a native Discord call transport or weakening app security implicitly.

**Architecture:** Calls use page evidence plus native capture state and a postcondition state machine. Apple Music uses a pure event reducer and one bounded helper lifecycle controller. Xcode and CLI both embed the same helper binary.

**Tech Stack:** Swift 6, WebKit, AVFoundation, XCTest, Xcode project settings, Apple Events diagnostics.

**Spec:** `docs/superpowers/specs/2026-09-29-c1.3.5-design.md`

## Global Constraints

- One persistent Discord WKWebView remains the only call surface.
- Capture state alone never means Discord call connected.
- No raw Discord credentials or native call transport.
- Exact Apple Music position is not advertised without a signed-build manual gate.
- Do not remove hardened runtime or alter sandbox entitlements in this plan.
