# C1.3.5 Build and Release Confidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use red-green-refactor for build-tool behavior, run fresh verification before every completion claim, and never stage generated app bundles or private state.

**Goal:** Make Xcode, SwiftPM tests, CLI packaging, and CI agree on the same C1.3.5 artifact and produce actionable verification output.

**Architecture:** One canonical edition metadata file feeds Xcode settings and shell/Python tools. The Xcode project owns the same helper/resource graph as the CLI build. A macOS CI workflow runs full Xcode verification; the local Command Line Tools path reports its exact missing resource tool instead of pretending to pass.

**Tech Stack:** Xcode project, SwiftPM, Swift 6, shell, Python, GitHub Actions, deterministic ZIP/SHA-256.

**Spec:** `docs/superpowers/specs/2026-09-29-c1.3.5-design.md`

## Global Constraints

- C1.3.5 metadata is the only release identity source.
- Build output and packages remain ignored.
- Local signing is not Developer ID signing or notarization.
- No CI secret, user session, credential, or recovery material is collected.
