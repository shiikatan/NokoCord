# C1.3.5 Tan Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use red-green-refactor for every behavior change, run focused persistence and UI tests, and never stage private Tan state.

**Goal:** Make Tan approval, failure, replacement, and recovery visible, confirmable, bounded, and reversible.

**Architecture:** The trust store remains the source of truth for package identity and recovery. Tan Hub, Inspector, and details consume one presentation model. Native requests are checked against package identity, content hash, capability, quota, origin, nonce, and payload limits before dispatch.

**Tech Stack:** Swift 6, SwiftUI, WebKit, XCTest, private atomic JSON storage.

**Spec:** `docs/superpowers/specs/2026-09-29-c1.3.5-design.md`

## Global Constraints

- Page-world Tans cannot call mutating native actions.
- Approval changes when code, target, capabilities, or trust origin changes.
- Trust records contain no credentials, Discord content, cookies, tokens, or raw bridge payloads.
- Replacement and recovery are atomic; failed Tans do not disable unrelated Tans.
- All trust-changing actions require clear user confirmation.
