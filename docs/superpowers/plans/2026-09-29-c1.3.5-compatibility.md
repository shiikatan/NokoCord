# C1.3.5 Compatibility Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use red-green-refactor for every behavior change, run the focused verification after each task, and review the diff before committing.

**Goal:** Complete feature-scoped Discord compatibility probing, visible recovery diagnostics, and selector-drift coverage without collecting page content.

**Architecture:** A bounded page probe returns semantic-anchor and browser-capability facts for one document generation. Swift reduces those facts into immutable per-feature states; the runtime gates each feature independently, while the Compatibility Center renders only sanitized status and recovery actions.

**Tech Stack:** Swift 6, WebKit JavaScript, SwiftUI, XCTest, fixture HTML.

**Spec:** `docs/superpowers/specs/2026-09-29-c1.3.5-design.md`

## Global Constraints

- Use one persistent Discord WKWebView; do not add a transport or second view.
- Probes inspect presence/type/capability facts only; never page content, tokens, cookies, or account identifiers.
- Unsupported or unknown probes disable only the affected Noko feature and preserve native Discord behavior.
- Hashed-class selectors must be named fallback entries with tests.
- Safe Mode remains zero scripts, handlers, bridges, and page-world hooks.
