# NokoCord Chiaki C1.3.5 Design

Status: approved implementation scope; security-sensitive signing changes remain
explicitly gated.

C1.3.5 is the confidence-and-recovery release after C1.3.0. It completes the
highest-value unfinished work from the C1.3.0 checklist without adding another
Discord transport, weakening the persistent-session boundary, or turning Tans
into an extension marketplace.

## Release objective

C1.3.5 should make the answer to these questions visible and testable:

1. Which Noko features are compatible with the current Discord document, and
   what remains native Discord behavior when one feature is unavailable?
2. What happened when a Tan, helper, call, or page integration failed, and can
   the user recover without losing the Discord session?
3. Does the Xcode path produce the same helper-inclusive artifact as the
   shipping CLI path, and can the complete verification gate run on CI?
4. Are accessibility, performance, and lifecycle behavior measured instead of
   inferred from a short manual session?

## Non-negotiable constraints

- Keep one persistent Discord WKWebView.
- Discord owns authentication, messages, media, and account state.
- Do not add raw-user-token, cookie, credential, CEF, broker-client, self-bot,
  remote-marketplace, or second-WebView behavior.
- Safe Mode remains a zero-Noko boundary and preserves the Discord data store.
- Page-world Tans receive no mutating native capability.
- New native capability requires a named contract, identity binding, payload
  and rate limits, lifecycle cleanup, and explicit UX review.
- Compatibility probes inspect bounded presence/type facts only; they never
  collect message text, account identifiers, cookies, tokens, or media.
- Generated packages, private recovery material, reports, and agent notes stay
  outside tracked source.
- Do not remove hardened runtime or change sandbox posture implicitly. The
  Apple Music Automation posture is a separately documented decision gate.

## Sub-project A — Compatibility Center and probe v2

Create a single probe coordinator that returns bounded facts for navigation,
message rows, composer, media/attachments, calls, notifications, and activity
dispatch. Each feature receives its own `unknown`, `healthy`, `degraded`, or
`unsupported` state and a sanitized reason. A missing anchor disables only the
affected Noko integration while Discord’s native surface remains usable.

Add a compact Compatibility Center reachable from the workspace toolbar and
Inspector. It shows the current route, document generation, feature status,
last probe time, and recovery action. It must not display raw selectors,
Discord content, or JavaScript exception text to ordinary users.

Add selector-drift, missing-anchor, unsupported-route, and Zen/reload fixtures.
Hashed-class selectors remain explicit fallback entries with a warning and a
test fixture, never an unlabelled default.

## Sub-project B — Tan recovery and trust UX

Extend the existing trust record with target, trust origin, last failure
category/time, and an explicit enabled state while preserving hash-bound
approval. Keep package replacement atomic and retain one previous package
snapshot.

Add a shared recovery surface to Tan Hub, Inspector, and details:

- package identity and trust diff before re-approval;
- last failure category and time;
- Retry, Disable, Start Safe Mode, Restore Previous Version, and redacted
  diagnostics;
- confirmation for trust-changing, restore, disable, and Safe Mode actions;
- a clear warning that page-world code runs beside Discord JavaScript.

Implement package-storage and translated-archive quotas, categorize helper
callback failures, and keep failed Tans isolated from unrelated Tans.

## Sub-project C — Calls and Apple Music confidence

For calls, add deterministic postcondition handling: a disconnect is complete
only after the active Discord call surface confirms leave and native capture is
`.none`. Add distractor-control fixtures, permission denial/recovery coverage,
minimize/reopen and sleep/wake state handling, and an explicit live-call gate.
No native call transport is introduced.

For Apple Music, finish reducer and helper lifecycle coverage: cold start,
pause/resume, stop, seek, repeat, next track, quit/relaunch, identity changes,
single-helper ownership, bounded reconnect, and termination after NokoCord
quits. Surface Automation denial and notification-only fallback accurately.
Exact-position support remains unadvertised until a signed-build manual gate
passes.

Add the missing NokoMusicWatch Xcode target/embed phase so Xcode and CLI builds
contain equivalent helpers. Do not drop hardened runtime as part of ordinary
C1.3.5 implementation; if the maintainer later approves that posture change,
it gets its own design, entitlement review, and release gate.

## Sub-project D — Performance, accessibility, and Tan polish

Add deterministic mutation-budget tests for 1,000 editor and message
insertions, observer teardown, and document-generation cancellation. Keep the
per-frame scan budget bounded and exclude editor mutations from unrelated work.

Complete Focus Shield and Code Workbench accessibility and reduced-motion
behavior. Add dynamic-rendering fixtures, keyboard-visible controls, VoiceOver
labels, focus restoration, and non-motion collapse/expand behavior.

Add Focus Shield profiles for screen sharing, meetings, and streaming only if
they remain presentation-only and capability-free. Profiles must not persist
Discord content or modify account state.

## Sub-project E — Verification and release confidence

Make `Package.swift`, Xcode, `scripts/build.sh`, and `scripts/verify.sh` agree
on resources, deployment target, bundle identity, helper inclusion, and test
entry points. Provide a CI-friendly full gate that uses a real Xcode host for
SwiftPM/XCTest/resource compilation; the local Command Line Tools limitation
must remain an explicit diagnostic rather than a false pass.

Keep deterministic ZIP/checksum packaging, shipped-byte privacy scans,
signature/entitlement/architecture checks, and an extraction verification.
Update the C1.3.5 checklist and release notes only from observed evidence.

## Success criteria

- Every C1.3.0 unchecked automated item that is in the C1.3.5 scope has a
  passing focused test or a recorded external-host gate.
- Compatibility failures are feature-scoped, bounded, visible, and fail open.
- Tan trust-changing actions are understandable, confirmable, and reversible.
- Calls and Apple Music never claim state they have not verified.
- Xcode and CLI release artifacts contain the same reviewed helper/resources.
- Performance and accessibility behavior has deterministic regression coverage.
- No credential, session, or private recovery material enters logs, fixtures,
  packages, commits, or release assets.
