# NokoCord Chiaki C1.3.5 Checklist

This is the executable checklist for the C1.3.5 confidence-and-recovery
release. Every checked item needs test output, a manual validation note, or an
explicit external-host exception. Generated packages, private session state,
recovery material, reports, and agent notes remain outside tracked source.

## 0. Release control

- [ ] Work only on `chiaki`.
- [ ] Do not synchronize Maomao or `noko`.
- [ ] Preserve the one persistent Discord WKWebView invariant.
- [ ] Preserve Discord ownership of authentication, messages, media, and
      account state.
- [ ] Add no raw-token, credential, cookie, CEF, broker-client, self-bot,
      marketplace, second-WebView, or native Discord call transport.
- [ ] Read current `AGENTS.md` before each implementation slice.
- [ ] Keep workstream write sets disjoint and review every returned diff.
- [ ] Keep generated artifacts, private state, and agent notes untracked.

## 1. Compatibility Center and probe v2

- [ ] Model bounded probe facts, feature states, sanitized reasons, route, and
      document generation.
- [ ] Probe navigation, messages, composer, media, calls, notifications, and
      activity prerequisites without collecting page content.
- [ ] Gate each feature independently and fail open when its probe is unknown or
      degraded.
- [ ] Label hashed-class fallbacks and test semantic-selector drift.
- [ ] Cover `/app` and `/channels/*`, login, settings, OAuth, invite, error,
      download, and unknown routes.
- [ ] Cover missing-anchor fixtures while native Discord behavior remains.
- [ ] Cover Zen/reload generation synchronization and stale probe callbacks.
- [ ] Add Compatibility Center status, recovery action, accessibility labels,
      and redacted diagnostics.
- [ ] Add deterministic 1,000-message and 1,000-editor mutation budgets.

## 2. Tan trust and recovery UX

- [ ] Persist target, capabilities, trust origin, enabled state, health,
      failure category/time, approved hash, last-known-good hash, and one
      previous package snapshot.
- [ ] Migrate older trust records safely without granting new trust.
- [ ] Enforce package and translated-archive quotas.
- [ ] Categorize helper callback failures without raw error retention.
- [ ] Show hash/target/capability/origin diffs before re-approval.
- [ ] Show failure category/time and accurate page-world trust warnings.
- [ ] Add Retry, Disable, Start Safe Mode, Restore Previous Version, and
      redacted diagnostics controls.
- [ ] Confirm every trust-changing, restore, disable, and Safe Mode action.
- [ ] Prove wrong origin/hash/nonce/capability/payload/rate/frame requests are
      rejected and all resources clean up.
- [ ] Prove one failed Tan does not stop unrelated Tans.

## 3. Calls and Apple Music

- [ ] Model call leave-requested, Discord-leave-confirmed, capture-cleared,
      and blocked-navigation states.
- [ ] Scope disconnect to the active call surface and cover distractor controls.
- [ ] Do not clear native call state before the Discord leave postcondition and
      capture `.none` are observed.
- [ ] Cover permission denial/recovery, minimize/reopen, sleep/wake, and stale
      generation behavior.
- [ ] Run the two-user, ten-minute live-call gate.
- [ ] Cover Apple Music cold start, pause/resume, stop, seek, repeat, next,
      quit/relaunch, identity changes, delayed events, and helper disconnect.
- [ ] Enforce one helper, bounded retry/backoff, heartbeat/stale detection, and
      exit after NokoCord quits.
- [ ] Keep missing/denied/unsupported/stale and notification-only fallback
      labels truthful.
- [ ] Do not advertise exact-position support before a signed-build manual gate.
- [ ] Keep hardened runtime/sandbox posture unchanged unless a separate
      security decision is approved.

## 4. Performance, accessibility, and Tans

- [ ] Bound observer work and prove the mutation budgets.
- [ ] Add Focus Shield screen-share, meeting, and streaming profiles without
      capabilities, network, persistence, or account mutation.
- [ ] Add Focus Shield active indicator, cleanup, Safe Mode, reduced motion,
      focus restoration, and accessibility labels.
- [ ] Add Code Workbench dynamic rendering, keyboard controls, focus behavior,
      VoiceOver labels, reduced motion, and source-preserving gutters.
- [ ] Keep copy as a user-gesture page action with no native clipboard bridge.
- [ ] Cover dynamic rendering, selector drift, enable/disable, and cleanup.

## 5. Build parity and CI

- [ ] Define C1.3.5 metadata and next build number in the canonical source.
- [ ] Add NokoMusicWatch as an Xcode target and embed phase.
- [ ] Match helper/resource graph, deployment target, bundle IDs, entitlements,
      and usage descriptions across Xcode and CLI artifacts.
- [ ] Make missing resource-tool diagnostics actionable without fake compilers.
- [ ] Add macOS/Xcode CI for SwiftPM/XCTest, Xcode Debug/Release, CLI build,
      verifier, privacy, package, and checksum gates.
- [ ] Verify fresh extraction matches the built app and exact ZIP digest.

## 6. Automated verification

- [ ] Full Swift/XCTest suite passes on an Xcode-equipped host.
- [ ] Broker suite passes.
- [ ] Translator suite passes.
- [ ] Compatibility/selector-drift fixtures pass.
- [ ] Trust migration/storage/rollback/quarantine tests pass.
- [ ] Call postcondition and Apple Music reducer/helper tests pass.
- [ ] Performance-budget tests pass.
- [ ] Xcode Debug and Release builds pass.
- [ ] Shipping CLI build and release verifier pass.
- [ ] Signature, entitlement, architecture, privacy, ZIP, and diff checks pass.

## 7. Manual release gates

- [ ] Existing Discord session survives relaunch and Safe Mode.
- [ ] Compatibility Center correctly reports supported and unsupported routes.
- [ ] Tan approval, hash change, trust diff, failure, restore, and quarantine
      flows work without losing the session.
- [ ] Calls pass readiness, permission, leave, minimize/reopen, sleep/wake, and
      live-call gates.
- [ ] Apple Music passes the documented fallback behavior and helper lifetime
      gate; exact position remains unclaimed unless signed access passes.
- [ ] Focus Shield profiles work for screen share/meeting/streaming and turn
      off cleanly.
- [ ] Code Workbench is keyboard and VoiceOver usable.
- [ ] Sixty-minute Discord session stays within the measured performance budget.
- [ ] Fresh ZIP extraction launches and matches the verified app.

## 8. Release publication

- [ ] Review every staged file against this checklist.
- [ ] Keep packages and private state out of Git.
- [ ] Run the final full verification gate and record any host exception.
- [ ] Update `RELEASE_NOTES.md` only from verified behavior.
- [ ] Create annotated tag `chiaki-C1.3.5` only after exact release approval.
- [ ] Push only `chiaki` and `chiaki-C1.3.5` when publication is authorized.
- [ ] Publish the GitHub Release with ZIP and checksum assets only when
      publication is authorized.
- [ ] Verify remote tag, branch, release body, asset names, sizes, and digests.
