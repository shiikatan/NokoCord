# NokoCord Chiaki C1.3.0 Release Checklist

This is the executable checklist for C1.3.0. Every checked item needs either
test evidence, a manual validation note, or an explicit release exception.
Generated packages, private state and agent notes stay outside tracked source.

## 0. Release control

- [ ] Confirm checkout is `chiaki`.
- [ ] Confirm no Maomao or `noko` branch synchronization is part of the work.
- [ ] Confirm the maintainer-approved scope is the C1.3.0 design document.
- [ ] Confirm no raw-user-token transport, credential extraction, CEF or broker
      production path has been added.
- [ ] Confirm the one-persistent-WKWebView invariant remains intact.
- [ ] Confirm current `AGENTS.md` has been read before each implementation
      slice.
- [ ] Confirm each implementation slice has a named owner and disjoint write
      set.
- [ ] Confirm generated reports, local packages, credentials, recovery
      material and agent notes are ignored and untracked.

## 1. Baseline and repository hygiene

- [ ] Record the starting commit, branch and release tag.
- [ ] Run `git status --short --branch`.
- [ ] Run the current release verifier against the current shipping bundle.
- [ ] Run translator tests.
- [ ] Run broker tests.
- [ ] Run `git diff --check`.
- [ ] Record current XCTest/Xcode availability.
- [ ] Preserve existing Discord/WebKit session data and private recovery files.
- [ ] Create no broad or destructive cleanup command.

## 3. AGENTS and reusable skills

## 4. Safe Mode and route gating

- [ ] Safe Mode installs zero Noko user scripts.
- [ ] Safe Mode installs zero Noko message handlers.
- [ ] Safe Mode preserves the Discord session data store.
- [ ] Exiting Safe Mode requires an explicit reload before scripts return.
- [ ] `/app` and `/channels/*` are recognized supported routes.
- [ ] Login, OAuth, settings, downloads and unrelated routes receive no Noko
      page mutation.
- [ ] Route changes update compatibility state without leaking old handlers.
- [ ] Existing enabled Tans remain recorded but do not execute in Safe Mode.
- [ ] Add a Discord-origin Safe Mode fixture; do not rely only on
      `fixture.invalid`.
